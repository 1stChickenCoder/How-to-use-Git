## Hiển thị trang thái với `git status`

Câu lệnh này sẽ hiển thị
- Đang ở branch nào.
- Trạng thái của branch hiện tại so với origin như thế nào (cái này nhiều lúc không chính xác vì dữ liệu đã được thay đổi trên origin, muốn chính xác thì phải `git fetch` để tải về dữ liệu mới nhất).
- Trạng thái các files trong dự án, file nào đang được `git track` (theo dõi).

Nếu chưa tạo nhánh nào thì sẽ mặc định ở master hoặc main.

`$ git status`

// On branch master
// No commit yet
// nothing to commit

* origin: trạng thái branch local so với trên server

Các khu vực theo thứ tự như sau:
1. **Khu vực làm việc**: là nơi thực hiện code, vẫn ở local
2. **Khu vực staging**: sau khi dùng `git add` thì file sẽ được đưa lên đây, vẫn ở local
3. **Khu vực commited**: sau khi dùng `git commit` thì file sẽ từ staging đưa lên đây, vẫn ở local
4. **Khu vực remote (origin)**: sau khi dùng `git push` thì file sẽ được commit lên đây, đây là ở trên server

**Mô tả luồng hoạt động tại các khu vực**
1. Ban đầu
`$ git status`
// On branch master
// ...
// Untracked files
// (use "git add...")
Khi này nó vẫn đang nằm trong khu vực làm việc

2. Đưa lên staging
`$ git add index html style.css`  // để đưa các file cần
hoặc 
`$ git add .`                     // để đưa tất cả các file

Kiểm tra lại trạng thái bằng `git status` sẽ thấy trạng thái "Changes to be committed". Hoặc nhấn vào source control và thấy được các file được add vào trong "Staged Changes".

Bên cạnh các file hiển thị trong "Staged Changes" có một dấu "-" nếu nhấn vào nó sẽ đưa các file quay trở lại "Khu vực làm việc".

Hoặc dùng lệnh sau:
`$ git reset index.html style.css`
`$ git reset .`


## Commit code với `git commit`

`$ git commit -m "Hãy viết tiêu đề của việc thay đổi code của bạn"`

Làm xong thì lại kiểm tra trạng thái của các file thôi!!!

Nếu lỡ commit mà không muốn thì thực hiện undo commit
